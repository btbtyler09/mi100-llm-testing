# Quark install on MI100 (gfx908) — MI100 addendum

Read this before SKILL.md on a gfx908 host. It overrides conflicting guidance. Status tags: **[measured]**,
**[spec]**, **[unverified]**.

**Verified install [measured, 2026-10-07]:** amd-quark 0.13 (universal PyPI wheel) in a fresh CPython 3.12 venv with
torch 2.10.0+rocm7.0 and torchvision 0.25.0+rocm7.0 imports on gfx908, JIT-compiles its kernels (needs `ninja` on PATH,
`PYTORCH_ROCM_ARCH=gfx908`) and lists 28 schemes. PTQ results are in `../quark-torch-llm-ptq/MI100.md`.

Recipe that works (each step fixed a real failure):

```bash
python3.12 -m venv quark-venv && . quark-venv/bin/activate
pip install "torch==2.10.0" --index-url https://download.pytorch.org/whl/rocm7.0
echo "torch==2.10.0+rocm7.0" > torch-constraint.txt
pip install -c torch-constraint.txt numpy ninja "amd-quark[cli]" datasets transformers accelerate
pip install --force-reinstall --no-deps "torchvision==0.25.0" --index-url https://download.pytorch.org/whl/rocm7.0
export PYTORCH_ROCM_ARCH=gfx908 PATH=$VIRTUAL_ENV/bin:$PATH
HIP_VISIBLE_DEVICES=<one idle card> python -c "from quark.torch import LLMTemplate; print(LLMTemplate.get_supported_schemes())"
```

Failures seen on the way [measured]:
- Without the constraint file, `pip install amd-quark[cli] transformers accelerate` replaced the ROCm torch with
  **CUDA torch 2.14.1+cu130 and the nvidia-* wheels** (the error later reads "NVIDIA driver on your system is too old").
  Always pin torch with `-c`, then confirm `torch.version.hip` is set and `pip list | grep -c nvidia` is 0.
- A dependency (timm) pulled the PyPI torchvision, which breaks `from transformers import PreTrainedModel`
  (`operator torchvision::nms does not exist`). Install the ROCm torchvision build with `--no-deps`.
- Missing `ninja` → "Stable-ABI hw_emulation extension could not be loaded and JIT compilation failed".
- **Quark touches the GPU at import** (moves an FP8-emulation lookup table to `cuda`), so with no visible GPU the import
  fails. A "CPU-only" smoke test is not possible; give it one idle card.

## Environment facts to record (Prerequisites step)

- Arch: `gcnArchName` reports `gfx908:sramecc+:xnack-`. Set `PYTORCH_ROCM_ARCH=gfx908` for any JIT/universal-wheel build so
  kernels aren't compiled for the wrong target. Keep `HSA_OVERRIDE_GFX_VERSION=9.0.8` if it is set (our convention; do not strip it).
- Existing GPU Python envs on our host:
  - our GPTQModel env — Python 3.13 **free-threaded** (3.13t), torch 2.10.0+rocm7.0, GPTQModel 7.3.5,
    transformers 5.16.1. Quark's 3.11–3.13 range presumably assumes the GIL build; 3.13t support is
    [unverified] — prefer a fresh standard-CPython 3.12 venv for Quark rather than modifying this one.
  - Serving containers (`btbtyler09/vllm-rocm-gfx908:*`) carry their own torch/ROCm; don't install Quark into them unless
    the plan says so.
- The GPU-readiness check in SKILL.md (`torch.cuda.is_available()` + a tensor op) is valid on ROCm. Before installing,
  check the cards are idle: `rocm-smi --showuse --showmemuse` plus `docker ps` (the "low-power state" warning does not
  mean idle). Long quant/serve jobs often hold all four cards.
- Visibility: use `HIP_VISIBLE_DEVICES` only (never together with `ROCR_VISIBLE_DEVICES`). on our host rocm-smi GPU0..3 =
  renderD130, 131, 128, 129, and an NVIDIA card sits at renderD132.

## Wheel choice

- Universal PyPI wheel: compiles Quark kernels on first use → needs `hipcc` for gfx908 (present in ROCm 7.0). First
  compile time on gfx908 [unverified]; budget for it (CK builds here have taken hours).
- Native wheels: an exactly matched gfx908 build is [unverified] to exist; don't assume one.
- If a Quark kernel fails to compile and the error mentions `v_pk_mul_f32`, DPP `row_newbroadcast`, FP8 or MFMA FP8/FP4
  instructions, that kernel targets gfx90a+/gfx94x+ and will not build on gfx908. Record it; don't retry with flags.

## What a gfx908 install is for

Useful schemes on this hardware are INT4/INT8 weight-only and possibly W8A8 int8 (see
`../quark-torch-llm-ptq/MI100.md`). FP8/MXFP4 are not deployable here (no hardware). Our known-good quantizer is
GPTQModel, not Quark; install Quark here only for a specific comparison or scheme GPTQModel lacks.

## Hardware facts (shared across our MI100 skills)

**Fan rule (our chassis; check yours):** the case fans follow GPU0's temperature only. A single-card bench or job runs on **GPU0**, or another job keeps GPU0 continuously loaded; otherwise the fans stay at idle speed and the loaded card reaches 95 °C junction within minutes (2026-10-07: GPU1 alone, GPU0 idle, hit 95 °C at both 200 W and 290 W; that was the fan artifact, not a card limit). For capability numbers, load all four cards at once (most realistic) and log junction for every card.

gfx908 CDNA1, 120 CUs, 32 GB HBM2 per card, 4 cards all-to-all xGMI (1 hop), 200 W cap by policy. No FP8/FP4 units;
bf16 MFMA is half the fp16 rate.
